The scenario

One agency, two kinds of customer

Parents write in with needs like "CPR-certified, weekends, handles nut allergies." Nannies come with résumés. The agency's assistant has to match them, answer policy questions, and draft bookings. It must never leak a nanny's phone number, give medical advice, or skip a parent's must-have requirement.

Architecture

How the pieces fit together

Notebook 1 turns raw documents into searchable data. Notebook 2 builds the agent that answers parents, and Notebook 4 makes it durable. Notebook 3 sits beside the agent and watches it: every call is traced, failures become evaluators, and the evaluators run in CI and in production.

The arc

Four notebooks, each building on the last

Each section starts by showing something going wrong, then adds the fix. By the end the reliability features are stacked on top of each other, and you've seen each one fail without its fix first.

What "reliable" means here

The agency's four definitions of a good reply

Notebook 3's evaluators don't target a generic quality score. They target four criteria that came from asking the agency owner what "good" looks like.

Understands constraints

Pulls out must-haves like CPR, weekend availability and allergy handling, and respects them.

Matches the parent's tone

Warm with an anxious first-time parent, brief and professional with a returning one.

Safe and compliant

Keeps a nanny's address and phone number private until a booking is confirmed.

Knows when to escalate

Hands medical, legal and off-topic questions to a person instead of answering them.

Spotlight · Notebook 3

Fast judge first, slow judge only when unsure

Jev is a System One model: it doesn't generate text. You give it the parent's query, the agent's reply and some typed questions, and one call returns calibrated probabilities. It answers the same way every time and costs a tiny fraction of a cent, but it can't reason through a policy. So the notebook builds a cascade: Jev answers every check, and only the answers it's unsure about go to an LLM judge.

  1. Clone and install 
    git clone https://github.com/ApurvaMisra/nanny-agency-workshop
cd nanny-agency-workshop
uv sync --all-extras
  2. Add your keys 
    cp .env.example .env
# set OPENAI_API_KEY (and optionally TYPESAFE_API_KEY)
  3. Generate the BAML client 
    uv run baml-cli generate --from baml_src
  4. Run the smoke test 
    uv run jupyter notebook notebooks/00_smoke_test.ipynb

    Every cell should print ✅ OK. For Notebook 4, also install the temporal CLI and run temporal server start-dev.

Full setup for macOS, Linux and Windows, with troubleshooting, is in SETUP.md.
