2. ReAct loop — one iteration

Inside the ReAct loop, BAML returns a typed AgentStep per turn. Python dispatches the named tool with the typed args, records the observation, and loops. 

sequenceDiagram
    autonumber
    participant U as User
    participant L as react_run loop
    participant B as BAML DecideWithTools
    participant T as Tool (Python)

    U->>L: user_message
    loop until finish or max_steps
        L->>B: history + user_message
        B-->>L: AgentStep { thought, tool_call, final_answer? }
        alt tool_call.name == "finish"
            L-->>U: final_answer
        else known tool
            L->>T: tool(**args)
            T-->>L: observation
            L->>L: append (Thought, Action, Observation)
        else unknown tool
            L->>L: record "<<error: unknown tool>>"
        end
    end

3. Multi-agent topology (Planner → Researcher → Executor)

Section 7 of the agent notebook splits the work across three role-bound BAML functions. An optional Critic step can ask the Executor to revise a draft that doesn't cite findings cleanly.

5. Memory and permissions side-flows

Short-term memory is an in-session dict; long-term memory is a JSON store keyed by parent_id. Permissions are enforced by wrapping tools so forbidden actions return a refusal observation. 

flowchart LR
    subgraph Memory
        direction TB
        SH[Short-term:
session dict] -.persist on confirm.-> LT[(MemoryStore
data/memory.json)]
        LT -.load on new session.-> SH
    end

    subgraph Permissions
        direction TB
        Agent[Agent decides tool_call] --> GT[gated_tool wrapper]
        GT -->|allowed| Tool[Real tool runs]
        GT -->|forbidden pre-confirm| Refusal[POLICY REFUSAL observation]
        Tool --> HITL{Booking-creating?}
        HITL -->|yes| Confirm[Wait for parent YES]
        HITL -->|no| Done[Continue]
        Confirm --> Done
    end
